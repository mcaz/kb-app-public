# 一般利用者向けインストールの実装範囲

2026-09-09更新。目的は、ソース取得やRust/Node/Terminal操作を利用者に求めず、
インストール、KB作成・復元、AI接続、最初の記録と検索へ進めることである。
現時点では配布準備と初回ガイドの部分実装であり、一般配布完了ではない。

## 初回と日常の画面

新しいKBの作成とGitHubからの復元は既存コアを使う。作成・復元をUI threadの外で
実行し、成功したSetupStateをqueryへ保存する前にAppへ次の画面の意図を渡す。
初回画面が外れたためにcallbackが失われる境界を回帰テストで確認する。
成功後はホームと接続設定を開き、失敗時には初回画面を維持して再試行できる。

設定の「はじめに」とホームから、次の使い方ガイドをいつでも開ける。

1. 既存の用途別AI登録・保護設定を行い、対象AIを再接続する。
2. コピーした依頼文で、本人が覚えておきたい事実・好みを通常ノートとして保存する。
3. 同じAIで検索し、候補の全文を取得してタイトル・ID・本文を確認する。
4. アプリ側の検索入口でも同じ記録を見つけられる。

ガイドは達成状態を持たない。登録済み、依頼文のコピー、ノート件数を、AIの保存・検索の
成功証拠へ変換しない。既存KBの更新時には初回ガイドを強制表示せず、通常操作を止めない。
個人のAGENTS.md/CLAUDE.md編集や人間向け汎用ノートエディターは導入しない。

## 配布準備

macOS候補はGit本体とGit LFSを同梱する。コアが実行path・helper・再帰PATHを揃え、
欠損・非通常ファイル・実行権限不備・PATH表現不能・異なる再帰Gitを起動前に拒否する。
明示overrideは`git`/`git-lfs`という実行名を必要とする。Tauriの開発出力では資材が
実行ファイルの隣へコピーされるため、配布app・準備sidecar・開発出力の配置を区別する。

- [公式Gitの準備と対応ソース](bundled-git.md)
- [macOS候補生成・署名・公証・同梱物の検査](macos-release.md)

開発用アプリの差し替えと、一般利用者に配布するDeveloper ID署名・公証を分ける。
新workflowは明示したmain commitから候補を生成・保持し、Release公開や更新配信は行わない。

## 未完了の受入

| 範囲         | 残る作業                                                            |
| ------------ | ------------------------------------------------------------------- |
| 同梱Git      | Intel build、HTTPS/TLS/認証の実受入                                 |
| 配布物       | Intelのapp/DMG生成、Developer ID署名・公証・Gatekeeper検証          |
| 初回操作     | clean Macと第三者で10分以内の初回記録・検索、通信失敗と再試行の実測 |
| 更新         | 配信先・署名鍵の設定、実配信からの次版取得と適用の実測              |
| 更新後の保全 | 更新元の共存試験receipt、実機での起動失敗復元、AI再接続の実確認     |
| Windows      | Windows配布物・保護機能・実機受入は後続のWindows対応で扱う          |

OS署名は更新物の署名の代わりにはならない。DB migration後にアプリだけを旧版へ
戻してデータも復元できたとは扱わない。更新実装と復旧条件を検証するまでは、
配布候補の検査成功だけをIssue全体の完了にしない。

公式取得物が不足した状態でも、合成fixtureとRust/画面ロジックは別々に検査できる。
`TAURI_CONFIG`でbundleの資材参照だけを空にしたRust検査はコード検証であり、
通常の配布設定によるbuild・資材同梱の受入証拠ではない。実資材の欠損は隠さず、
候補生成前に通常設定でも検証する。

2026-09-09に公式Git/LFS入力のchecksumを照合し、arm64の実ビルド、PATHを限定した
Git/LFSのpush・fresh clone・LFS実体復元・rebase/autostashが成功した。
通常設定のapp build、署名後の同梱Git/LFS受入、本人TerminalでのDMG作成と内容照合も
完了した。配置済み765a845の全appInventoryは候補と一致し、strict署名、稼働MCPの契約版、
既存KBのDB/Markdown照合と初回ガイド表示・遷移を確認した。
これらは開発機arm64での候補受入であり、Developer ID/公証、clean Mac、第三者の
10分以内の初回操作、全AIクライアントの受入を完了したものではない。

LFS準備scriptは一時HTTP・通信失敗を各経路で最大3回試し、通常URLが復旧しない
場合は固定asset IDの[公式GitHub API](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)
へ切り替える。各試行はbody受信を含め30秒、checksum一致時だけcacheへ確定する。
恒久HTTPエラーやchecksum不一致を再試行成功として隠さない。

[アプリ更新と互換性検査](app-updates.md)は、設定画面、署名と内容の検査、全KBの診断、
旧bundleの保持と起動受入までソースへ接続した。合成の失敗試験と実署名の検査は、
公開鍵・配信先を設定した実更新の受入とは別に扱う。
